Why there are so many

The suite did not bloat. The project quadrupled in July.

Source went from 5,844 to 26,821 lines in twenty-seven days — a 4.6× jump. Tests grew 4.8× over the same window, which is why the ratio between them barely moved.

Lines of test code per line of source. A suite that was genuinely bloating would show this climbing. It fell by more than half since May, then held — the shape of tests keeping pace with code, not outrunning it.

Do not trim.

There is no bloat to cut. The suite is green, cheap per test, and proportionally leaner than it was in May. The number is large because the project is large.

If CI time is the real concern, two fixes are worth more than any amount of deleting — and neither costs a single assertion.

Risk

What deleting would actually cost

Version-surface checks, skill-registration counts, changelog and diagram-drift guards. Each exists because that failure happened before. Removing one to save 20 milliseconds re-opens a known wound.
