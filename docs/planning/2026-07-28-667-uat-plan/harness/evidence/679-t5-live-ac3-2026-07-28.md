# #679 T5 — live end-to-end AC3 evidence (2026-07-28)

Retained because a Step-4 finding correctly observed that the earlier "verified via spike" claim had
no durable artifact behind it. This is the exact shipped invocation against a live herdr server, not
an injected frame. Also serves as UAT check **W2** evidence.

Procedure: split a throwaway pane off `w1:pCX`, `herdr agent start uat679 --kind claude --pane <new>
-- --permission-mode default` (auto mode auto-approves, so nothing would ever block), start
`python3 -u hooks/pane_watch_lib.py watch --source poll --poll-interval-s 2 --heartbeat-s 8
--sender-cmd 'cat >> <log>'`, send a prompt that requires a Bash approval, then `esc`, then close the
pane. Driver script kept at `<scratchpad>/t5b.sh` (it references session paths, so it is not
committed).

## RUN A — before the `state_change_seq` fix: the watcher SAW the block and did NOT notify

    t+1: working 3
    t+2: blocked 3          <-- agent_status changed, `revision` did NOT
    herdr agent explain: state=blocked, rule=generic_permission_prompt
                         (region=after_last_horizontal_rule priority=840)
    notifications sent: NONE
    heartbeat: {"events": 2, "notified": 0, "polls": 17, "poll_failures": 0}

The input layer was demonstrably alive (`polls` climbing, no failures) and the block was real. The
frame was emitted and then REFUSED by `Reconciler.accepts`, which requires a strictly newer key:
`revision` 3 was not greater than baseline 3. **herdr bumps `revision` on pane-record changes, not on
every `agent_status` transition** — the earlier `1 -> 3` measurement spanned two transitions and hid
this. So the dead transport was only the FIRST of two independent reasons the watcher could never
fire; this is the second, and no unit test could have found it because every fixture supplied its own
revision numbers.

`state_change_seq` lives on `snapshot.agents[]`, not on `snapshot.panes[]`, and it advanced 2148 ->
2151 across the transition that left `revision` unmoved. It is the key #612's first design wanted and
abandoned because the `pane.updated` EVENT does not carry it — the SNAPSHOT does, so the poll path
can have what the event path never could.

## What this evidence does and does not establish

- **Establishes:** a real block on a live pane produces exactly one notification through the shipped
  CLI; the body carries no pane contents (the prompt text `touch /tmp/uat679-permission-probe` and
  the "Do you want to proceed?" screen never appear in it); `esc` clears the block and does not
  re-notify; the heartbeat's `polls` counter distinguishes a live input layer from a dead one.
- **Does not establish:** that the notification reaches a phone and reads usefully at 3 a.m. (W8 is
  an owner-only check, deliberately not attempted); behaviour across a herdr daemon restart (the
  regression guard's live path is unit-tested only, and the guard deliberately fails loud rather than
  assuming herdr's persistence contract).
- **Follow-up worth filing, not done here:** the body identified the pane as `w1:pC0` because the
  snapshot's PANE record carried no `label`/`name`, while the AGENT record carried `name: uat679`.
  Merging that name would make the 3 a.m. message far more legible. Left out deliberately — it is a
  body/identity change, it touches the AC5 provenance boundary, and #679 is about the input layer.
