Owner acceptance testing

The worker must become the pane's own process — never a child beside it.

The build seat launches through herdr pane run <pane> exec <argv> — a call herdr neither documents nor endorses. If a future herdr release ever wraps that command in a child instead of replacing the pane's shell, every PID the supervisor holds names the wrong process: it would track and kill a shell while the real worker kept running. Nothing would error. Play both outcomes below, then work the three remaining checks.

WebGL is unavailable here, so the animated view is off. The claim in words: one process is replaced in place — the PID stays 2978249 while /proc/2978249/cmdline changes from /bin/bash to the worker's argv. In the regression case the shell keeps PID 2978249 and the worker appears as a separate PID, so the supervisor's recorded identity points at the shell.

    GAP-3

    Unusable from the cron / headless launcher ACCEPTED

    pane split --current resolves the caller's own pane. A detached cron run has none, so a build-seat launch there fails loud. "herdr for the build seat" and "unattended cron-resumed runs" are mutually exclusive.

    Decided 2026-07-27 (D-4, "A-656: accept"): accepted as a scope boundary. No follow-up issue. This closed UAT-6.

    GAP-4 · #659

    No herdr coverage in CI, and the gate is manual PARTLY

    CI installs no herdr, so no herdr behaviour is exercised there at all. #639's gate is the compensating control — but it is run deliberately by a human from inside a pane.

    The structural CI gap stays by design. The "nobody noticed herdr changed" half is now #659. A live instance turned up the same day: herdr wait …, which the herdr skill documents, does not exist in the installed 0.7.5 binary.

    GAP-5 · #647

    status output for a herdr job is not trustworthy SHIPPED

    The read-only run-status probe ran tmux unconditionally, ignoring record.terminal_backend. For a herdr record it failed for an ordinary reason and the caller derived exited_no_sentinel without surfacing that the probe itself had failed.

    Fixed and merged: 6ef34c5 (PR #657, v3.97.2). The probe now resolves the record's own backend, and an operational failure derives liveness_unknown instead of asserting the job is dead (D-3 chose AC2). Rollback anchor c3baac5. Redeploy the plugin to get it — the cache is still 3.97.1.
