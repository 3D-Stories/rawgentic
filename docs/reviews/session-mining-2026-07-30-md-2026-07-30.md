## Summary

The artifact attributes reported failures across model behavior, workflow machinery, scope ratification, dispatch configuration, and handoff controls, then proposes six interventions. Several load-bearing counts and causal verdicts are not reproducible from the evidence presented, and two acknowledged failure paths remain uncovered by the proposed controls.

## Findings

### 1. [High] completeness · high confidence — §9 Coverage honesty

> Miners read user text, assistant text, and tool-call headers (≤400 chars/message); tool results and file diffs were not systematically inspected — churn counts are lower bounds.

The report labels code defects, data leaks, parser behavior, launcher state, and fix-introduced regressions as confirmed, but its disclosed collection method did not systematically inspect the tool results or diffs needed to establish those facts. Quoted assistant narration cannot independently verify those technical conclusions, so the causal verdicts and resulting interventions may require a new evidence pass.

**Recommendation:** Add a claim-evidence appendix covering every retained High: transcript event ranges, relevant tool-result excerpts, diff or commit identifiers, verifier identity, and disposition. Reclassify technically unverified claims as reported allegations until that primary evidence is inspected.

### 2. [Medium] completeness · high confidence — §10 Recommended actions, item 2

> **Stop-hook circuit breaker + goal scoping.** N consecutive fires with no file-delta → pause + notify-owner.

The proposed circuit breaker is not implementable as stated because `N`, the observation window, reset conditions, and the meaning of “file-delta” are unspecified. File changes are also an incomplete progress signal for owner decisions, remote operations, waiting, review, or handoff work, so compliant sessions can be paused while genuine deadlocks can continue after irrelevant file edits.

**Recommendation:** In Recommended action 2, define the threshold, time window, reset rules, and goal/session identity. Replace the sole file-delta test with an explicit progress-event model that includes file changes, tool outcomes, owner-blocked state, verified successor activity, and repeated identical stop reasons.

### 3. [Medium] completeness · high confidence — H5 precedent and §10 Recommended actions, item 5

> Precedent in the other direction (confirmed): 07-27, `7a8ba96d` — an owner-authored `/goal` targeting lumenquire landed in a twi-bound session; the model complied and re-bound (74 stop-hook fires, 3 corrective interrupts: *"shit / we are in thewanderinginn project"*). Cross-project goal text is a hazard from both sides.

The report identifies cross-project goal injection as the reverse half of the handoff hazard, but Recommended action 5 only blocks `ad-hoc-handoff` from selecting a project different from the registry. An owner-authored `/goal` can therefore still target another project, trigger rebinding, and recreate the documented stop-hook incident.

**Recommendation:** Extend Recommended action 5 with an inbound `/goal` gate: when the goal’s project differs from the pane registry, require an explicit owner confirmation naming both projects before rebinding or arming the goal.

### 4. [Medium] consistency · high confidence — H3 — phases are not farmed out

> 23 of 24 active projects have no `executorRouting` config (confirmed live by session `d7117a76`, 07-30, via the canonical `^DISPATCH` census: 102 rawgentic-reviewer vs 52 executor:review, 17 rawgentic-implementer vs 14 executor:analysis).

The cited census includes 17 `rawgentic-implementer` entries immediately after the report claims zero build/implementation dispatches, but it does not explain whether these are actual invocations, configuration declarations, another time window, or non-build uses. Without aligned scope and units, this evidence cannot support the categorical H3 verdict.

**Recommendation:** For each census, specify the time window, project set, counted object, and whether the values are invocations or configuration references. Reconcile the 17 implementer entries explicitly with “Build/implementation dispatches: zero.”
**Ambiguity:** The report does not define what the `^DISPATCH` census counts or whether its scope matches the 30-run census.

### 5. [Medium] correctness · high confidence — Verdicts, H1 row

> | H1 | "opus-5 … missing instructions and going off and doing whatever it wants" | **PARTIALLY CONFIRMED — a real, smaller set of genuine failures, sitting inside two system problems that manufacture the same feeling: goal-machinery defects and a consent-quality gap** | 28 confirmed highs; 16 refuted |

The artifact supplies no hypothesis-level allocation showing that 28 and 16 are H1 counts, so the headline numerically overstates or at least conflates H1 evidence with investigation-wide results.

### 6. [Medium] correctness · high confidence — H4 — the tier rationalization is not the culprit

> **But every rule the confirmed failures violated still exists in the current tiers**, and the mining pass produced 1 medium H4 finding in 155. The failures are pressure-shaped, not knowledge-shaped.

A rule’s continued semantic existence does not establish that rationalization had no causal effect. The artifact itself says enumerated checklists and the stop-and-ask list were compressed, and later reports repeated failures of standing-decision freshness. The evidence therefore does not distinguish knowledge loss from reduced salience, discoverability, or enforcement, so the “pressure-shaped, not knowledge-shaped” conclusion is unsupported.

**Recommendation:** Change the H4 verdict to “not established from this window,” and evaluate pre/post miss rates for the moved or compressed rules, including prompt placement and retrieval context. Define what the denominator “155” counts.

### 7. [Medium] internal-consistency · high confidence — H3 — phases are not farmed out

> **Model census** (82 transcripts): **42,007 of 42,037 assistant messages are claude-opus-5** (30 fable-5, 50 synthetic).

The 30 Fable messages exactly consume the 30-message remainder after subtracting 42,007 from 42,037, leaving no room for the stated 50 synthetic items if all three numbers describe assistant messages. If “synthetic” refers to transcripts, events, or overlapping classifications, that population is not identified.

**Recommendation:** Rewrite the census with mutually exclusive categories that sum to 42,037, or explicitly label the 50 synthetic items as a separate population and state whether they overlap with model-attributed messages.
**Ambiguity:** The unit and overlap status of “50 synthetic” are undefined.
